A recommender never finds out whether the floor emptied.

Engines like Spotify's answer one question extremely well — given this track, what sounds like it? — from audio features and what millions of other listeners did next. But they are open loop. They know what was played. They never learn how the room reacted.

Kadenz closes that loop with a camera. Point it at people moving and it measures the response, then re-ranks the same catalogue an open-loop model ranks blind. Both run side by side below, so you can watch them disagree.

This runs entirely in your browser. The pose model is downloaded once (~13 MB) and every frame is measured and discarded on your own machine. There is no server in this build: no video, no audio and no measurement is uploaded anywhere. Read the code — it is the page you are on.
What this browser demo does and does not do
Person detection, pose, tracking Real. The same YOLOv8-pose weights as the desktop app, exported to ONNX
Crowd energy, per-person energy, floor flux Real, but measured by frame differencing rather than the desktop's dense optical flow — coarser, and it is what drives the recommender here
Both recommenders Real code. A port of engine/dj.py; the catalogue is generated from the Python so the two cannot drift
BPM, groove sync, level Real when you allow the microphone, from spectral flux rather than librosa. Denied or silent, they stay blank — never invented
The catalogue itself Real releases, used as recognisable labels — but their tempo, key and 0–1 feature values are estimates assigned by hand, not retrieved from Spotify or anywhere else

A webcam sees one room, not a dancefloor. Expect one or two people and a modest energy range — the crowd numbers in the README come from real venue footage.
